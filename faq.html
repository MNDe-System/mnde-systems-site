What does MNDe actually do?

MNDe is an execution boundary: it validates a request, computes a deterministic ALLOW or REFUSE decision, and only then executes or refuses. The decision happens before any cost is incurred, not after.

See the pipeline

Why are decisions deterministic?

The same input always produces the same decision and the same hashes, because the decision is a pure function of the request and a versioned policy. Nothing depends on timing, ordering, or runtime.

Run the determinism test

Is the decision made in my browser?

No. The browser only sends inputs and renders the response. Every ALLOW/REFUSE decision is computed server-side by /api/simulate and returned with a request and decision hash.

What is in the proof bundle?

A ZIP with a manifest, drift report, parity report, replay report, and a sample decision. Its SHA-256 is published so you can confirm the file you downloaded is the one described.

What happens when I submit the contact form?

Your request is validated and sanitized, then queued and routed for review, returning a real request ID and timestamp. If mail is not configured or sending fails, you get an explicit error — never a fake success.
